# Ouroboros — สเปก (ร่าง v0.1)

> เรื่องเบื้องลึกที่ไม่มีใครรู้ แม้แต่ตัวระบบเอง จนกว่าจะถึงเวลา

## ปัญหา

LLM เขียนเรื่องไปข้างหน้าทีละเทิร์น ระหว่างเทิร์นไม่มีที่ไหนเก็บความคิดไว้ ถ้ามันคิดว่า "คนร้ายคือพ่อบ้าน" แล้วไม่ได้เขียนไว้ เทิร์นหน้าความคิดนั้นก็หายไป เรื่องจึงลากไปเรื่อย ๆ ปมที่ปูไว้ไม่ถูกเก็บ และไม่มีตอนจบที่วนกลับมาหาตอนต้น

ทางแก้ที่ user ต้องกำกับเองก็ทำให้ไม่มีอะไรน่าประหลาดใจเหลือ

## หลักการ

1. **จำสิ่งที่ปูไว้ แล้วค่อยหยิบมาเฉลย** ไม่ต้องให้โมเดลวางแผนล่วงหน้าเก่ง แค่จำได้ว่าเคยปูอะไรไว้ เรื่องก็ดูเหมือนวางแผนมาตั้งแต่ต้น
2. **มีแผนลับ แต่ยังไม่ตัดสินใจ** วางชะตาไว้หลายทางพร้อมกัน (A B C) แล้วค่อยล็อกทางที่เข้ากับสิ่งที่เกิดขึ้นจริงที่สุด หักมุมจึงเข้ากับปมที่ปูไว้เสมอ และเดายาก เพราะแม้แต่ระบบเองก็ยังไม่ได้เลือก
3. **ส่งให้คนเขียนเรื่องแค่ที่จำเป็น** โมเดลที่เขียนเรื่องเห็นแค่ช่วงของเรื่อง ปมที่ควรหยิบ และความลับที่ห้ามเผย ไม่เห็นแผนทั้งหมด จะได้ไม่รีบวิ่งไปหาตอนจบหรือใบ้แรงเกินไป
4. **user คุมทิศทางได้โดยไม่ต้องรู้เนื้อหา** เห็นแค่ตัวเลขและอารมณ์ แอบดูได้ทีละขั้นถ้าอยาก

## คำศัพท์

| คำ | ความหมาย |
|---|---|
| **ปม** (seed) | สิ่งที่โผล่ในเรื่องแล้วยังค้าง: ของ คน ความลับ คำสัญญา คำถาม สถานที่ |
| **ชะตา** (fate) | แผนหนึ่งทาง: ความจริงเบื้องหลัง หักมุม และตอนจบ มีได้หลายชะตาพร้อมกัน |
| **ล็อกชะตา** | เลือกชะตาเดียวเป็นความจริงของเรื่อง ชะตาอื่นถูกตัดทิ้ง |
| **ช่วงเรื่อง** (phase) | ปูเรื่อง → ไต่ระดับ → จุดเปลี่ยน → วิกฤต → ไคลแมกซ์ → คลี่คลาย |
| **องก์** (arc) | เรื่องย่อยหนึ่งเรื่องที่มีช่วงเรื่องครบในตัว ใช้ในแผนยาวและมหากาพย์ |
| **ผู้เก็บปม** (Scout) | งานเบื้องหลังที่อ่านข้อความล่าสุดแล้วดึงปมออกมา ใช้โมเดลถูกได้ |
| **ผู้ทอชะตา** (Architect) | งานเบื้องหลังที่เขียน ให้คะแนน ตัด และล็อกชะตา ควรใช้โมเดลเก่ง |

## โจทย์และโทรป (ไม่บังคับ)

ตอนเริ่มเรื่อง user เลือกได้สามแบบ

| แบบ | ทำอะไร |
|---|---|
| **ไม่ใส่** (ค่าเริ่มต้น) | ผู้ทอชะตาอ่านการ์ด persona และข้อความแรก แล้วคิดเอง ประหลาดใจที่สุด |
| **ใส่เอง** | พิมพ์โจทย์คร่าว ๆ (เช่น "มีคนในบ้านไม่ใช่คนที่เขาอ้าง") และ/หรือเลือกชิปโทรป |
| **โทรปลับ** | ระบบสุ่มโทรป 1–2 อันจากหมวดที่ user ติ๊กไว้ แต่ไม่บอกว่าอันไหน แผงแสดงแค่ "มีโทรปลับ 2 อัน" แอบดูได้แบบเดียวกับชะตา |

- ชิปโทรปมีชุดสำเร็จรูปแบ่งหมวด (ปริศนา · ความสัมพันธ์ · การเดินทาง · ดาร์ก · แฟนตาซี) เช่น ศัตรูกลายเป็นคนรัก · ห้องปิดตาย · ตัวตนที่ซ่อนไว้ · การทรยศจากคนใกล้ตัว · วนลูปเวลา · ผู้ถูกเลือกที่ไม่อยากถูกเลือก · คำสาปที่มีราคา · พิมพ์เพิ่มเองได้
- โจทย์และโทรปเป็น "วัตถุดิบ" ของชะตา ไม่ใช่คำสั่ง: ชะตาบางทางอาจใช้ บางทางอาจบิด เพื่อให้ยังเดาไม่ได้ว่าจะออกมาแบบไหน
- โจทย์ที่ user พิมพ์เองไม่ถูกส่งให้คนเขียนเรื่องตรง ๆ ส่งผ่านผู้ทอชะตาเท่านั้น

## ขนาดแผน

user เลือกตอนเริ่ม (เปลี่ยนกลางเรื่องได้ ระบบจะคำนวณช่วงเรื่องใหม่)

| ขนาด | ความยาวประมาณ | ชะตาพร้อมกัน | ล็อกชะตาที่ | โครงสร้าง |
|---|---|---|---|---|
| **สั้น** | 40–80 ข้อความ | 2 | ~50% (จุดเปลี่ยน) | 1 องก์ |
| **กลาง** | 100–200 ข้อความ | 3 | ~60% | 1 องก์ |
| **ยาว** | 250–500 ข้อความ | 3 (เรื่องหลัก) + 2 ต่อองก์ | องก์: ~60% ขององก์ · เรื่องหลัก: ~70% | 2–4 องก์ |
| **มหากาพย์** | 500+ ไม่จำกัด | 3 (เรื่องหลัก) + 2 ต่อองก์ | องก์: ~60% ขององก์ · เรื่องหลัก: เมื่อ user กด "เข้าสู่บทสุดท้าย" | องก์ต่อกันไปเรื่อย ๆ |

- นับเฉพาะข้อความที่มองเห็นในแชท (ไม่นับข้อความที่ซ่อน)
- ถึงเป้าแล้วไม่บังคับจบ ระบบเข้าช่วงคลี่คลาย แล้วถามว่าจะปิดเรื่อง หรือเปิดองก์/ภาคใหม่ต่อ
- **วงงูกินหาง** ในช่วงไคลแมกซ์และคลี่คลาย ผู้ทอชะตาต้องหยิบปมจากช่วงปูเรื่องอย่างน้อย 1 ข้อมาเฉลย ตอนจบจึงวนกลับมาหาตอนต้น

### ช่วงเรื่องตามสัดส่วน

| ช่วง | สัดส่วนของความยาว |
|---|---|
| ปูเรื่อง | 0–15% |
| ไต่ระดับ | 15–45% |
| จุดเปลี่ยน | 45–55% |
| วิกฤต | 55–75% |
| ไคลแมกซ์ | 75–90% |
| คลี่คลาย | 90–100% |

ผู้ทอชะตาเลื่อนช่วงเร็วหรือช้ากว่าสัดส่วนได้ไม่เกิน ±10% ถ้าเนื้อเรื่องจริงยังไม่พร้อม (เช่น user ยังไม่เจอเบาะแสสำคัญ)

## ชะตาคู่ขนาน (A B C)

### วงจรชีวิตของชะตา

```
เกิด ──► มีชีวิต ──► (ให้คะแนนทุกรอบ) ──► ล็อก ──► เป็นความจริงของเรื่อง
                      │
                      └──► ถูกตัด (ขัดกับเรื่องจริง หรือคะแนนต่ำ) ──► ปมของมันกลายเป็น "ปมหลอก"
```

- **เกิด** ตอนเริ่มเรื่อง ผู้ทอชะตาเขียนชะตาตามจำนวนในตารางขนาดแผน แต่ละชะตาต้อง**ต่างกันจริง** (คนร้ายต่างคน แรงจูงใจต่างแบบ หรือโทนตอนจบต่างกัน) ไม่ใช่แค่สลับรายละเอียด
- **ให้คะแนน** ทุกรอบของผู้ทอชะตา (0–100) จากสามอย่าง: เข้ากับสิ่งที่เกิดขึ้นจริงแค่ไหน · ใช้ปมที่ปูไว้ได้กี่ข้อ · ตรงกับอารมณ์ที่ user เลือกแค่ไหน
- **ตัด** เมื่อเรื่องจริงขัดกับชะตาจนแก้ไม่ได้ (เช่น ตัวละครที่ชะตา B ต้องใช้ตายไปแล้ว) หรือคะแนนต่ำกว่าเกณฑ์ติดกัน 2 รอบ ก่อนถึงจุดล็อก ถ้าเหลือน้อยกว่าจำนวนที่ตั้งไว้ ผู้ทอชะตาเขียนชะตาใหม่มาแทนได้ (ไม่เกินช่วงไต่ระดับ)
- **ล็อก** เมื่อถึงจุดล็อกตามขนาดแผน ชะตาคะแนนสูงสุดกลายเป็นความจริง ความจริงของมันเข้ารายการ "ความลับที่ห้ามเผย" จนกว่าจะถึงจังหวะเฉลย ล็อกก่อนเวลาได้ถ้าชะตาอื่นถูกตัดหมด

### ปมกับชะตา

ปมแต่ละข้อติดป้ายว่าชะตาไหนใช้ได้ (`fates: ["A","C"]`)

- ก่อนล็อก คนเขียนเรื่องได้รับปมที่**ใช้ได้กับหลายชะตา**ก่อน (เบาะแสที่ตีความได้สองทาง) เรื่องจึงเปิดทางไว้ทุกชะตา
- ห้ามส่งความจริงของชะตาใดชะตาหนึ่งให้คนเขียนเรื่องก่อนล็อก ส่งได้แค่ "ทิศทาง" ที่ทุกชะตาที่ยังมีชีวิตอยู่ไปด้วยกันได้
- **ปมหลอก** ปมของชะตาที่ถูกตัดไม่ทิ้งไปเฉย ๆ ผู้ทอชะตาเลือกได้ว่าจะปล่อยไว้ หรือเฉลยว่าเป็นการชี้นำผิดทาง (red herring) เรื่องจะดูลึกขึ้น

### แผนยาวและมหากาพย์

ชะตามีสองชั้น:

- **ชะตาเรื่องหลัก** ความลับใหญ่ที่สุดของทั้งเรื่อง ล็อกช้า
- **ชะตาองก์** ปมเฉพาะองก์ปัจจุบัน ล็อกและเฉลยภายในองก์ องก์ที่จบแล้วเหลือแค่สรุปสั้น ๆ กับปมที่ยังค้างส่งต่อให้องก์ถัดไป

ปมหนึ่งข้ออาจเป็นขององก์และเรื่องหลักพร้อมกันได้ (ปมที่เฉลยครึ่งเดียวในองก์ แล้วเฉลยเต็มตอนจบ)

## สองบทบาท สองโมเดล

ตั้งค่าแยกกันใน Extensions → Ouroboros

| บทบาท | ทำเมื่อไหร่ | ค่าเริ่มต้น | แนะนำ |
|---|---|---|---|
| ผู้เก็บปม | หลังบอทตอบทุกครั้ง (หน่วง 2 วินาที รวมหลายข้อความเป็นรอบเดียวได้) | ใช้ API เดียวกับแชท | โมเดลถูกและเร็ว |
| ผู้ทอชะตา | ทุก N ข้อความของบอท · เมื่อช่วงเรื่องเปลี่ยน · ถึงจุดล็อก · กดปุ่มเอง | ใช้ API เดียวกับแชท | โมเดลเก่งที่สุดที่มี |

N ตามขนาดแผน: สั้น 6 · กลาง 8 · ยาว 10 · มหากาพย์ 12 (ปรับได้)

- เลือกได้จาก **Connection Profile** ของ ST (Connection Manager) ส่งผ่าน `ConnectionManagerRequestService.sendRequest()` จึงไม่สลับ API ของแชทที่ใช้อยู่ ถ้าไม่ได้เลือก หรือ ST รุ่นเก่าที่ไม่มี Connection Manager ใช้ `generateRaw` กับ API ปัจจุบัน
- งานเบื้องหลังไม่แทรก preset ของแชท ไม่แทรก OOC ของ As you command และไม่ปลุกการวัดของ Memory Horizon
- ไม่ทำงานระหว่างที่แชทกำลัง generate ข้อความ รอให้เสร็จก่อน

## ข้อมูลที่เก็บ

เก็บใน `chat_metadata.ouroboros` ติดไปกับไฟล์แชท

```json
{
  "version": 1,
  "owner": { "chatId": "…", "avatar": "…", "groupId": null },
  "size": "medium",
  "moods": ["มืด", "หักมุมแรง"],
  "premise": "",
  "tropes": ["ตัวตนที่ซ่อนไว้"],
  "secretTropes": { "categories": ["ปริศนา"], "picked": ["…"] },
  "phase": "rising",
  "arc": { "index": 1, "startedAt": 0, "summary": "" },
  "seeds": [
    {
      "id": "s7",
      "text": "จดหมายปิดผนึกที่ยายฝากไว้ ยังไม่มีใครเปิด",
      "kind": "object",
      "msgId": 42, "swipeId": 0,
      "fates": ["A", "C"],
      "status": "open",
      "paidAt": null
    }
  ],
  "fates": [
    {
      "id": "A", "layer": "main",
      "truth": "…", "twists": ["…"], "ending": "…",
      "needs": ["s3", "s7"],
      "score": 72, "lowStreak": 0,
      "status": "alive",
      "prunedAt": null, "pruneReason": ""
    }
  ],
  "nextBeat": "…",
  "secrets": ["…"],
  "lastArchitectAt": 40,
  "history": [{ "at": 40, "event": "pruned", "fate": "B" }]
}
```

- `kind`: `object` · `person` · `secret` · `promise` · `question` · `place` · `wound` (ปมในใจตัวละคร)
- `status` ของปม: `open` · `paid` (เฉลยแล้ว) · `herring` (ปมหลอก) · `dropped`
- `status` ของชะตา: `alive` · `pruned` · `locked`

### swipe ลบข้อความ แตกกิ่ง

- ปมผูกกับ `msgId` + `swipeId` ถ้า swipe ไปทางอื่น ปมจาก swipe เดิมถูกพักไว้ (ไม่ส่ง) และกลับมาถ้า swipe กลับ ถ้าลบข้อความ ปมของข้อความนั้นถูกลบ
- แตกกิ่ง / checkpoint / Save as: แผนติดไปด้วย (กิ่งใหม่ควรได้แผนเดิม) ตัดปมที่ `msgId` เกินความยาวของแชทใหม่ทิ้ง แล้วจำ `owner` ใหม่
- ย้อนแชทกลับไปก่อนจุดล็อก: ไม่ปลดล็อกเอง แต่แผงจะเสนอปุ่ม "ปลดล็อกชะตา"

## ส่งอะไรให้คนเขียนเรื่อง

แทรกด้วย `setExtensionPrompt` ในแชท @ ความลึก 3 role System (ปรับได้) ทุกเทิร์น ตัวอย่าง:

```
[ผู้เขียนจดไว้ส่วนตัว — ห้ามเอ่ยถึงบันทึกนี้ในเรื่อง]
ช่วงเรื่อง: ไต่ระดับ (ประมาณ 35%) — ค่อย ๆ เพิ่มแรงกดดัน ยังไม่ใช่เวลาเปิดเผยความจริง
จังหวะถัดไป: ให้มีคนที่สองสนใจจดหมายของยาย
ปมที่ควรหยิบมาเล่น (เล่าอ้อม ๆ ไม่ต้องอธิบาย):
- จดหมายปิดผนึกที่ยายฝากไว้
- รอยไหม้บนมือของคนสวน
ห้ามเผยก่อนเวลา:
- (ก่อนล็อกชะตาไม่มีรายการนี้)
```

- ส่งปมไม่เกิน 3 ข้อต่อเทิร์น
- ไม่ส่งรายชื่อชะตา ความจริง หรือตอนจบ จนกว่าจะล็อก และหลังล็อกก็ส่งแค่ในรูป "ห้ามเผย" กับ "จังหวะถัดไป"
- แม่แบบแก้ได้ในตั้งค่า ใช้ `{{phase}}` `{{beat}}` `{{seeds}}` `{{secrets}}`
- ปุ่ม 👁 แสดงข้อความที่จะถูกส่ง (ซ่อนไว้หลังปุ่ม "ยอมรับว่าจะเห็นสปอยล์")

## ส่งอะไรให้ผู้ทอชะตา

ข้อมูลเข้า:
- ข้อความล่าสุด (ตามงบ token ที่ตั้งไว้) และสรุปจาก **Memory Hub** ถ้าติดตั้งไว้ (เรื่องที่หลุดจาก context ไปแล้ว)
- การ์ดตัวละครและ persona แบบย่อ
- แผนปัจจุบันทั้งหมด (ปม ชะตา ช่วงเรื่อง ขนาดแผน อารมณ์ที่ user เลือก)

ข้อมูลออก: JSON ตาม schema ด้านบน (เฉพาะส่วนที่เปลี่ยน) ถ้า parse ไม่ได้ ลองใหม่ 1 ครั้ง ถ้ายังไม่ได้ เก็บแผนเดิมไว้ แล้วแสดงป้ายเตือนเล็ก ๆ (ไม่มีเนื้อหา)

## ส่งอะไรให้ผู้เก็บปม

ข้อมูลเข้า: ข้อความล่าสุดของบอท (และของ user ก่อนหน้า) กับรายการปมที่เปิดอยู่ (แค่ข้อความสั้น ๆ ไว้กันซ้ำ)
ข้อมูลออก: ปมใหม่ 0–3 ข้อ และ id ของปมเดิมที่ดูเหมือนถูกเฉลยแล้ว ผู้เก็บปมไม่เห็นชะตา จึงไม่ติดป้าย `fates` เอง ผู้ทอชะตาติดให้รอบถัดไป

## แผงที่ไม่สปอยล์

เปิดจากเมนู 🪄 → Ouroboros · `/ouro` · ปุ่มลอย (เก็บเข้า Quick Dock ได้)

**หน้าหลัก** (ไม่มีเนื้อหาของแผนเลย)

- วงงูกินหาง แบ่งเป็นช่อง 6 ช่องตามช่วงเรื่อง ช่องที่ผ่านมาแล้วเติมสี
- "ปูไว้ 7 ปม · เฉลยแล้ว 3"
- "ชะตาที่ยังเป็นไปได้: 3" หรือ "ชะตาถูกล็อกแล้ว"
- ขนาดแผน และองก์ที่เท่าไหร่

**คุมทิศทาง**

| ปุ่ม | ทำอะไร |
|---|---|
| อารมณ์ | ชิปเลือกได้หลายอัน: มืด · มีหวัง · โศก · อบอุ่น · หักมุมแรง · ลึกลับ · โรแมนติก — มีผลกับคะแนนชะตา |
| ตัดด้าย | ทิ้งชะตาทั้งหมดที่ยังไม่ล็อก แล้วเขียนใหม่ (ปมยังอยู่) ใช้เมื่อรู้สึกว่าเรื่องกำลังไปทางที่ไม่ชอบ โดยไม่ต้องรู้ว่าทางนั้นคืออะไร |
| ทอชะตาตอนนี้ | เรียกผู้ทอชะตาทันที ไม่ต้องรอครบ N ข้อความ |
| ขอปิดเรื่อง / เข้าสู่บทสุดท้าย | เลื่อนไปช่วงไคลแมกซ์ (มหากาพย์ใช้ปุ่มนี้ล็อกชะตาเรื่องหลัก) |

**แอบดู** (ต้องกดยืนยันทุกครั้ง) ทีละขั้น ต่อชะตาหรือต่อปม:

1. **กลิ่น** — คำเดียวบอกธีม เช่น "การทรยศ"
2. **เงา** — หนึ่งประโยคคลุมเครือ
3. **เปิดหมด** — ความจริง หักมุม ตอนจบ

ระดับที่เคยดูแล้วจำไว้ และแสดงป้าย "แอบดูแล้ว" บนหน้าหลัก

**ปมที่เปิดอยู่** แสดงเป็นรายการได้ (ปมคือสิ่งที่เกิดในเรื่องอยู่แล้ว ไม่ใช่สปอยล์) แต่ซ่อนป้ายชะตาของปม · แก้ ลบ หรือเพิ่มปมเองได้ ปมที่ user เพิ่มเองมีน้ำหนักมากกว่าปกติ

**ชะตาที่ไม่ได้เกิด** คลังชะตาที่ถูกตัด: "ถ้าเรื่องไปอีกทาง จะเป็นแบบนี้"

- แต่ละชะตาแสดงความจริง หักมุม ตอนจบ ถูกตัดตอนข้อความที่เท่าไหร่ เพราะอะไร (`pruneReason`) และปมไหนของมันกลายเป็นปมหลอก
- กดปุ่มไปที่ข้อความที่ชะตานั้นถูกตัดได้ เห็นว่าเรื่องแยกทางตรงไหน
- เปิดได้เต็มที่หลังปิดเรื่องหรือจบองก์นั้น ก่อนหน้านั้นต้องกดยืนยัน เพราะการรู้ว่าอะไร "ไม่จริง" ก็เป็นสปอยล์ได้ (บอกใบ้ว่าความจริงเหลือทางไหน)
- ชะตาที่ถูกเขียนทิ้งด้วยปุ่ม **ตัดด้าย** ก็อยู่ในคลังนี้ด้วย
- ปุ่ม **ใช้ชะตานี้เริ่มเรื่องใหม่**: ส่งชะตาที่ไม่ได้เกิดไปเป็นโจทย์ลับของแชทใหม่ (ทำทีหลังได้ ไม่อยู่ใน v0.1)

### กันสปอยล์โดยไม่ตั้งใจ

- toast และข้อความแจ้งเตือนไม่มีเนื้อหาของแผน ("ทอชะตาเสร็จแล้ว" ไม่ใช่ "ตัดชะตา B แล้ว")
- รายงานตรวจปัญหา (`/ouro-debug`) ซ่อนข้อความของชะตาและความลับ
- โมเดลที่คิดก่อนตอบอาจพูดถึงบันทึกลับในส่วน `<think>` แนะนำให้ซ่อนส่วนคิดของโมเดล (หน้าตั้งค่าบอกวิธี)
- user ที่ตั้งใจเปิด prompt inspector ของ ST ยังเห็นแผนได้ ส่วนนี้ไม่แก้ เป้าหมายคือไม่ให้เห็นโดยบังเอิญ

## เชื่อมกับ extension อื่น

| extension | ใช้ทำอะไร |
|---|---|

## ขอบเขตเวอร์ชัน

**v0.1**
- ผู้เก็บปม ผู้ทอชะตา Connection Profile แยกกัน
- ขนาดแผน 4 แบบ ช่วงเรื่อง ชะตาคู่ขนาน ล็อก ตัด ปมหลอก
- แทรกเข้า prompt ตามแม่แบบ
- โจทย์ ชิปโทรป และโทรปลับ (ไม่บังคับ)
- แผงหน้าหลัก คุมทิศทาง แอบดู รายการปม คลังชะตาที่ไม่ได้เกิด
- แชทกลุ่มแบบพื้นฐาน (ถ้าไม่หนัก ดูหัวข้อแชทกลุ่ม)
- องก์ซ้อน (ชะตาสองชั้น) ของแผนยาวและมหากาพย์
- ผู้ทอชะตาอ่านสรุปความจำจาก Memory Hub
- จัดการ swipe ลบข้อความ แตกกิ่ง
- ตั้งค่า: profile ของสองบทบาท · N · ความลึก/role · แม่แบบ · งบ token ของผู้ทอชะตา

**v0.2**
- ตัวตรวจความลับรั่ว: หลังบอทตอบ ถามผู้เก็บปมว่าข้อความนี้เผยความลับข้อไหนก่อนเวลาหรือเปล่า ถ้าใช่ เตือนหรือ swipe ใหม่ให้เอง (เลือกได้)
- เชื่อม Memory Hub เต็มรูปแบบ (เริ่มแชทใหม่ต่อเรื่องแล้วแผนตามไป) และปุ่มลอย + Quick Dock

## ค่าใช้จ่ายโดยประมาณ

ต่อข้อความของบอท 1 ข้อความ:
- ผู้เก็บปม: เข้า ~1–2k token ออก ~200 token
- ผู้ทอชะตา (ทุก N ข้อความ): เข้า ~4–8k token ออก ~1–1.5k token

ใช้โมเดลถูกเป็นผู้เก็บปมแล้ว ค่าใช้จ่ายส่วนใหญ่มาจากผู้ทอชะตา ซึ่งเรียกห่าง ๆ

## แชทกลุ่ม

ไม่ใช่เป้าหลัก ทำแบบพื้นฐานเพราะต้นทุนต่ำ:

- `chat_metadata` ของแชทกลุ่มใช้ได้เหมือนแชทเดี่ยว จำเจ้าของด้วย `groupId`
- ผู้เก็บปมเห็นชื่อผู้พูดของแต่ละข้อความ ผู้ทอชะตาได้การ์ดของสมาชิกทุกคนแบบย่อ
- แทรกบันทึกลับเหมือนกันทุกสมาชิก (ไม่แยกว่าใครรู้อะไร)
- ถ้าทำแล้วติดปัญหาที่ต้องแก้ลึก (เช่น ลำดับการพูดของ ST ชนกับงานเบื้องหลัง) ตัดออกจาก v0.1 ได้ แล้วแสดงว่า "ยังไม่รองรับแชทกลุ่ม"
